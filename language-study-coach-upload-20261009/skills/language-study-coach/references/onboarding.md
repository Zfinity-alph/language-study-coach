# Learner interview

On first use, invite a structured grill-style interview to understand the learner. Ask one high-impact question or closely related group per round. Use answers to select teaching depth, materials, practice, and feedback; explain consequential choices briefly.

Cover relevant dimensions without copying any example learner's answers:

1. Russian level, optional evidence or previous work, goals, deadline, materials, and weak points.
2. English level, optional exam subscores or previous work, exam or practical goals, deadline, and weak points.
3. Weekly study time, current language priorities, typical inputs and tasks.
4. Explanation language and depth, answer-reveal preference, correction strictness, and desired output practice.
5. Vocabulary, root expansion, note formats, reference templates, and storage preferences.
6. Review, tests, error records, research expectations, and permission to save a private profile.

Both languages are supported equally; a learner may study only one or allocate unequal time. Do not require identifying information, proof of scores, or answers unrelated to teaching. Do not repeat answered questions.

## Non-blocking behavior

Allow skipping, pausing, or deferring the interview. A blank or partial profile does not block note creation. If the user supplies a task now, prioritize it after a brief interview invitation; do not force completion or repeatedly restart onboarding. Ask only task-critical questions, such as a missing output directory when saving is requested.

Summarize stated level, evidence, goals, constraints, preferences, and unknowns for confirmation. Separate self-report, observed performance, and hypotheses. A single error is not a permanent ability label. Update the picture through subsequent feedback, without guessing missing facts.

## Persistence

An optional blank [learner profile template](../assets/learner-profile-template.md) is bundled. Copy and fill it only when saving is authorized; never fill the public template in place or insert private answers into the released skill.

Without permission, use the profile only in the current conversation and do not promise cross-session recall. With permission, save it in a user-approved private location, not in this skill or a public repository. Store only confirmed parameters and clearly marked observations. Scheduling reminders requires separate authorization.
